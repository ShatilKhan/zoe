Product decision record · proposed

What the product commits to.

The product decision record keeps scope, rationale, evidence, and release gates. These are its main points.

User and job

Patients need one private history they can correct, query, and share selectively. Clinicians need a narrow, time-limited view of patient-selected facts.

Selected experience

Android-first app: record entry, local medicine-name lookup with patient confirmation, automatic Rx area suggestion with field review, sourced chat, optional wellness reading, and encrypted share. Clinician access is a small web viewer.

Why this cut

A full path proves the core idea and the Presage integration within the challenge deadline. Booking and clinician verification remain later decisions.

Options considered

Cloud AI chat would expose readable record context to another service. Booking first would leave the record journey unfinished. A fully local app would remove link sharing. The selected path keeps local answers and patient-approved encrypted sharing.

Safety boundary

Medicine and diet questions are in scope. Zoe cites known facts and gaps. It does not diagnose, prescribe, choose a dose, or decide treatment.

Data rule

Readable records, chat, OCR, and sensor values stay on the phone. A patient-approved share uploads selected ciphertext and access metadata.

Success measure

A synthetic-data demo completes sign-in → reviewed record → sourced answer → live wellness session → selected share → clinician view → revoke. Critical safety and privacy gates must pass.

Cloud boundary

Selected encrypted share bundles and minimal account metadata may leave the phone. Readable record data stays on the patient device until the chosen clinician decrypts it.

Design guidance · proposed

Quiet utility with a clear point of view.

The design contract defines tokens, component states, content rules, responsive behavior, and screen checks. This review uses warm stone, deep forest, and a restrained citron accent. Large task titles and distinct surfaces give each journey a clear rhythm.

Brand mark

Use the supplied black Zoe mark at its original proportions. The transparent cutout supports splash, patient sign-in, vault unlock, and clinician sign-in. Keep one plain light background and enough clear space.

Information order

Answer or task first. Then source, uncertainty, and next action. Use dates and provenance on every record fact and saved reading.

Navigation

Five Android destinations use icons with short labels: Home, Records, Ask, Wellness, Share. Profile and Help open from Home. Keep the chat composer above the keyboard. Honor system Back and insets.

Type and spacing

Large compact sans titles, quiet uppercase section labels, and a readable system sans for details. Body copy stays legible at large text settings. Standard controls have at least 48 dp touch targets and clear focus states.

Components

Use a dark focus panel for the active task, grouped white record surfaces, forms for correction, status labels for provenance, one primary action per screen, and inline review before save. Photo import starts without a mandatory crop. Keep button and field shapes consistent.

State language

Distinguish Draft, Patient reported, Reviewed, Active, Expired, and Unknown. Never use color alone. A failed model, OCR line, speech pack, sensor, or share has a specific recovery step.

Accessibility

Give every icon action an accessible name. Use tooltips only for icon-only actions in the web review. The labeled navigation needs no tooltip. The Android app needs content descriptions for icon-only controls and at least 48 dp touch targets. Keep short navigation labels visible on touch. Check contrast, large text, reduced motion, English/Bengali copy, and chart values in text.

Visual restraint

No medical stock photos, fake doctor badges, glowing AI effects, colored diagnosis scores, or decorative dashboards. Color marks an action or state.

04A / Technical architecture

One build. Three runtime zones.

The phone runs the private work. Supabase relays only identity, grants, and ciphertext. The clinician browser opens a selected share. Build tools and QA telemetry have separate paths.

Local answer path

Records and food data feed local retrieval. Code calculates nutrients. Qwen3 explains facts; answer checks validate sources and numbers.

Share path

The phone encrypts selected facts. Supabase checks each download. The clinician browser uses the fragment key to decrypt.

Build secret path

Infisical protects development credentials. EAS secret variables supply build jobs. No Infisical token or Supabase service key ships in the APK.

06B / Assistant logic and interface

Make the chat useful and correctable.

  1. Detect record, medicine, nutrition, or help intent.
  2. Retrieve only relevant confirmed facts and pinned sources.
  3. Keep imported text in an untrusted data block.
  4. Use Qwen3 for wording and one clarifying question.

18 / Explicit assumptions

These limits define the proposal.

Device

Android first

Use a physical Android phone. The mic demo needs Android 13+ and an offline language pack. iOS follows later.

Privacy

Encrypted relay

Cloud services may hold ciphertext and account/share metadata. No cloud model reads records.

Clinician

Self-declared role

A clinician can sign in and read an invited bundle. The app does not verify credentials.

Prescription

Patient confirms text

Bengali and unclear handwriting use manual input.

Safety

No treatment claims

Medicine questions stay in scope. The assistant cites evidence and gaps. It does not prescribe or make a treatment decision.

Data

Synthetic demo

Do not enter real patient records before a separate security and recovery review.

Product decision still needed: If encrypted bytes cannot leave the phone, remove link sharing. The rest of the selected architecture stays the same.
